# ADR 0001：本地优先与 PWA / Tauri 双端

- 状态：已接受
- 日期：2026-10-27
- 决策者：星河一叶Roxy

## 背景

目标用户是在考研、考公、四六级、证书类考试中自驱学习的人。他们经常在地铁、图书馆、断网环境里复习；考试资料和错题带有较强的个人隐私属性。项目由个人维护，没有预算长期承担服务器、数据库和运维成本。

同时，用户明确要求移动端与电脑端都能使用，并在保证体验的前提下尽量小、轻便。

## 决策

1. v0.1 采用**本地优先**架构：数据保存在浏览器 IndexedDB，不设账号与服务端。
2. 移动端与桌面端共用一套响应式 Web 代码，v0.1 以 **PWA** 交付。
3. 桌面原生壳在 v0.2 使用 **Tauri 2**，复用同一份前端产物，使用系统 WebView。
4. 数据迁移通过带 `schemaVersion` 的 JSON 备份完成；v0.1 不做自动云同步。
5. 对存储被浏览器回收、清站点数据等风险，通过持久化请求、定期备份提醒和导入前摘要来缓解。

## 结果

正面：

- 无服务器成本，离线可用，隐私边界清晰。
- 一套 UI 与业务代码覆盖双端，维护成本低。
- PWA 没有安装包，桌面端 Tauri 安装包目标 ≤ 20 MB，明显小于 Electron。
- 数据完全可导出，用户不被锁定。

负面：

- 多设备同步需要手动导出/导入。
- iOS 可能回收长期未使用 PWA 的存储，必须在产品里持续提醒备份。
- PWA 在部分系统上的安装入口和应用商店存在感弱于原生包。
- 本地数据损坏或误清空时，恢复依赖用户自己的备份。

## 备选方案

- **Spring Boot + PostgreSQL + Vue**：更贴近传统企业栈，但需要服务器、部署和运维，违背零成本与离线优先。
- **Electron**：开发简单，但安装包 80–150 MB，与“轻便”目标冲突。
- **Flutter**：双端表现好，但需要另一套语言与渲染栈，桌面端包体和中文输入体验需要额外验证。
- **纯云端**：多设备体验更好，但隐私、成本和合规负担都不适合个人开源项目的第一版。

## 后续

- v0.2 增加 Tauri 2 桌面壳，并验证 Windows WebView2 的安装引导。
- 需要同步时，优先评估 WebDAV / S3 兼容存储，采用逐记录时间戳与墓碑字段处理冲突，而不是直接引入复杂 CRDT。
- 若上架移动应用商店，再评估 Tauri 2 mobile 或 Capacitor，不提前抽象。
