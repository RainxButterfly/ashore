# ADR 0002：使用收敛后的 SM-2，而不是完整 FSRS

- 状态：已接受
- 日期：2026-10-27
- 决策者：星河一叶Roxy

## 背景

错题需要在合适的时间回到复习队列。完整 FSRS 能更精细地拟合记忆稳定性与可提取性，但参数多、实现与调参成本高，对 v0.1 的个人项目而言会挤占产品闭环和双端体验的精力。

同时，用户需要理解“为什么下一次是 3 天后”，而不是面对一个无法解释的黑箱。

## 决策

实现一个收敛后的 SM-2：

- 评分四档：忘记、困难、记得、简单。
- 初始 ease 2.5，限制在 1.3–2.8。
- 首次成功：记得 1 天，简单 3 天。
- 忘记：间隔归零，10 分钟后再次出现，reps 重置，lapses + 1。
- 困难：间隔 × 1.2，ease -0.15。
- 记得：间隔 × ease，ease 不变。
- 简单：间隔 × ease × 1.3，ease +0.15。
- 最大间隔 365 天。
- 调度状态直接存在 `ReviewItem` 上，不引入单独的算法表。

## 结果

正面：

- 纯函数、可单测、可解释；复习按钮可以直接展示下一次间隔。
- 无需拟合参数，也不依赖用户历史量。
- 状态字段少，导入导出和未来迁移都简单。

负面：

- 不如完整 FSRS 贴合个体记忆曲线。
- 对连续失败、长期成熟卡片的处理比较粗糙。
- 四档评分仍依赖用户主观判断。

## 备选方案

- **完整 FSRS**：效果上限更高，但实现、参数拟合与解释成本超出 v0.1 范围。
- **Leitner 盒子**：实现最简单，但间隔粒度太粗，无法表达“困难/简单”的差异。
- **Anki 的完整 SM-2**：包含更多修正项，代码与边界条件更多，不适合第一版。

## 迁移路径

如果需要升级到 FSRS：

1. 在 `ReviewItem` 上增加稳定性、难度、可提取性等字段；
2. 保留现有 `dueAt` 作为回退值；
3. 用独立模块实现新调度器，通过设置项或版本开关灰度；
4. 为迁移写数据层测试，并更新备份 `schemaVersion`。

当前实现只借鉴 SM-2 的公开思想，没有复制任何第三方实现代码。
